## 7. 第一阶段：把 Incident 原型变成真实 ProofLoop

这是所有后续页面的前置条件，未完成不得进入花哨扩展。

### 7.1 自主调查编排器

将手动点击多个按钮改成一个可暂停、可重试、可恢复的调查工作流：

```text
Incident创建
→ 自动开始Trace
→ 收集SCADA与告警
→ 振动/叶片/健康诊断
→ 查询RUL
→ 查询相似历史故障与维修知识
→ 构建根因假设
→ 评估证据契约
→ 请求缺失证据或进入决策
```

要求：

- 复用现有 Diagnosis Orchestrator、Agent tools 和 Playbook。
- 每一步有状态、输入摘要、输出摘要、开始/结束时间、错误和重试次数。
- LLM 不可用时降级到规则/统计流程。
- 调查刷新页面后可恢复，不能只存在内存。
- 同一 Incident 重试不得重复创建证据、工单和 Trace。

### 7.2 证据契约

建立类型化证据：

```text
observation
model_prediction
rule_inference
llm_hypothesis
human_confirmation
conflicting_evidence
missing_evidence
verification_result
```

每条证据必须包含：

- 来源类型和来源 ID
- 采集时间与有效期
- 单位
- 置信度或质量等级
- 数据/输出摘要哈希
- 是否直接观测
- 支持或反驳哪个假设

算法至少包含：

1. 证据完整度：必需证据满足数 / 必需证据总数。
2. 新鲜度衰减：过期证据降低权重。
3. 来源可靠度：传感器、规则、模型、LLM、人工使用不同基准权重。
4. 冲突检测：同一变量在相近时间窗口出现不兼容值。
5. 最小确诊门槛：证据不足时只能输出“候选诊断”。

必须有单元测试证明：缺少关键证据时不能升级为确诊。

### 7.3 真实告警相关性与风暴压缩

不得只按字符串去重。实现可解释的加权告警图：

```text
边权 =
  时间接近度
  + 同风机/同部件
  + 部件拓扑邻近度
  + 同工况
  + 已知因果规则
  + 信号相关性
```

可使用阈值图连通分量、Union-Find 或轻量 DBSCAN 聚类，但必须：

- 真正使用 `window_minutes`
- 保留事件时间
- 保留合并前原始告警 ID
- 生成主告警选择依据
- 生成压缩率与误合并测试
- 重复运行幂等

### 7.4 真实资源约束决策孪生

替换固定模板和固定资源状态。决策输入必须来自已有系统或最小资源影子：

- RUL 及不确定性
- 实际/预计发电功率
- 电价配置及来源
- 当前故障严重度
- 人员技能、班次和占用
- 当前工单
- 备件库存、预留、在途和到货时间
- 天气窗口
- 历史同类维修成功率
- 方案的维修时间和安全约束

算法使用明确的多准则决策模型：

1. 统一各维度单位和方向。
2. 输出安全、经济、资源、恢复时间和可执行性分项。
3. 硬约束不满足的方案标记 infeasible，不能仅扣分。
4. 对可行方案计算可解释效用分。
5. 对不确定输入执行确定性种子的 Monte Carlo 或场景采样。
6. 输出置信区间、敏感性排序和方案翻转点。

禁止：

- `personnel_available=True`
- `parts_available=True`
- `weather_compatible=True`
- 固定风险 5/20/45
- 预先写死“预计损失”和“恢复概率”

数据不足时输出 `insufficient_data` 和缺失字段，不得生成貌似精确的数字。

### 7.5 策略强制执行

策略检查必须成为所有高风险写操作的服务器端必经门：

```text
请求
→ RBAC
→ 风险分级
→ 前置条件
→ 策略判定
→ 审批
→ 幂等执行
→ 审计记录
```

必须实现并测试：

- 证据不足不能确诊。
- 未审批的 L3 动作不能执行。
- 未通过恢复验证不能进入 `resolved`。
- 备件未锁定、人员不满足、天气不安全时不能开始维修。
- LLM 输出不能直接变更状态。
- Policy API 返回拒绝后，绕过 UI 直接调用状态接口仍然被拒绝。
- 并发请求不会重复审批或重复执行。

### 7.6 真实飞行记录

Incident 创建或调查开始时自动创建 Trace。每一次真实动作写入 Span：

- Agent 调用
- 模型调用
- 工具调用
- 检索
- 证据生成
- 策略判定
- 状态转换
- 人工审批
- 工单创建
- 恢复验证

Span 至少记录：

- 父子关系和步骤顺序
- 输入/输出摘要或哈希
- 工具/模型/Playbook 名称及版本
- 开始、结束和耗时
- Token、费用（能取得时）
- 错误、重试和降级
- 策略结果

不得把空 Trace 当作完成。完整演示 Trace 必须包含真实 Span，状态最终为 completed 或 failed。

### 7.7 恢复证明

事件不能靠填写 note 直接关闭。实现恢复验证服务：

- 选择维修前基线窗口
- 选择维修后观察窗口
- 比较振动、温度、功率、健康指数、告警复发和 RUL
- 检查观察时间是否充分
- 输出 pass / conditional / fail / insufficient_data

可采用：

- 稳健 z-score
- 中位数/MAD
- CUSUM 或变点检测
- 阈值与持续时间规则

输出 Recovery Certificate：

- 指标前后对比
- 验收阈值
- 观察窗口
- 使用算法和版本
- 数据来源
- 剩余风险
- 证据哈希

conditional 或 fail 状态不得关闭 Incident。

### 第一阶段验收

- 一个事件能通过单一入口自动运行至审批/验证阶段。
- 直接绕过策略接口无法关闭事件。
- 决策方案随人员、备件、天气和 RUL 变化而变化。
- Trace 包含真实 Span。
- 缺关键证据时诊断停留在候选状态。
- 验证失败时事件自动回到 executing 或 escalated。
- 后端全量测试与前端构建通过。

### 8.4 审计签名链 N-11

- 每条记录包含前一哈希

- 验证接口检查链连续性、内容哈希和签名
- 密钥不进入仓库
- 密钥缺失时 fail-safe，并明确降级状态

4. 使用与决策孪生相同的模型重算。
5. 通过确定性种子的场景模拟输出分布。
6. 展示实际路径、替代路径、差异、假设和不确定性。

不得写死“灾难路径损失 ¥131,400”。只有模型实际计算出结果时才能展示。

必须基于真实反馈记录，不得预置“采纳率 62%→84%”冒充结果。

建议算法：

- 方案采纳：Beta-Bernoulli 后验或带衰减的分类统计。
- 人员/方案偏好：有正则的在线权重更新。
- 工时校准：EWMA 或分层比例校准。
- 风险偏好：只作为推荐个性化输入，不能降低硬安全规则。

页面显示样本量、时间范围和不确定性。样本不足时显示“尚不可校准”。

### 9.2 事故复盘知识飞轮 B10

事件关闭后：

1. 生成结构化复盘草稿。
2. 提取候选知识。
3. 与已有知识去重。
4. 人工审核。
5. 在历史回放场景上评测。
6. 达标后发布新版本 Playbook。
7. 保留旧版本和回滚能力。

未经审核和评测的知识不能自动成为生产规则。

### 9.3 故障基因图谱 N-12

不得只定义字典然后计算一个装饰性 cosine。

要求：

- 明确数值、序数、布尔和类别特征编码。
- 缺失特征有显式处理。
- 可使用 Gower distance 或正确归一化后的混合特征距离。
- 给出 Top-K、相似度分解和鉴别检查建议。
- 使用现有已标注案例做留一或交叉验证。
- 输出准确率、Top-K 命中率或混淆矩阵；样本不足时明确限制。

### 9.4 时序因果发现 N-05

作为探索性辅助，不得把统计相关性表述为确定因果。

至少实现：

- 平稳性检查
- 滞后阶数选择
- Granger 检验或同等级可解释方法
- 多重检验校正
- Bootstrap 稳定性
- 与部件拓扑/物理规则交叉验证

页面标注“候选因果关系”，展示滞后、显著性、稳定性和物理解释。

### 9.5 Agent-to-Agent 资源协商 N-02

实现多 Incident 对稀缺资源的可审计协商：

- 资源请求
- 资源锁
- 安全风险
- 经济损失
- 紧急度
- 等待时间公平性
- 胜者、失败者及升级路径
- 并发事务

不能只排序列表。必须有锁定、冲突检测、释放、超时和重新协商。

## 14. 算法通用标准

每个被称为“算法”“智能”“学习”“因果”“概率”“优化”的模块必须包含：

1. 问题定义。
2. 输入、输出和单位。
3. 使用假设。
4. 算法或公式。
5. 为什么适合当前场景。
6. 数据不足行为。
7. 边界条件。
8. 单元测试。
9. 最小基线对比。
10. 可解释输出。
11. 版本和可复现随机种子。

禁止：

- 随机数直接当预测结果。
- 固定百分比冒充模型输出。
- 固定 Demo 文案冒充 LLM/算法解释。
- 预置漂亮增长曲线冒充历史指标。
- 用 seed 数据冒充真实用户行为。
- 把相关性称为因果。
- 把哈希链称为绝对不可篡改。
- 用 try/except 吞掉错误并返回成功。
- 只实现 API，不连接真实工作流和页面。
- 只实现页面，不实现后端和验收。
