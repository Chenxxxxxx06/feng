## 2. 对外统一口径

### 项目名称

**风调预顺 WindOps ProofLoop**

### 类别定位

**面向风电运维的可验证闭环工业 Agent**

### 一句话价值

**不只是预测哪里可能坏，而是让每一次诊断、决策和关闭都携带可追溯证据。**

### 核心问题

**传统 PHM 系统往往停在“发现异常、给出建议”；真实运维还需要完成资源校验、安全审批、工单执行和恢复验证。工单关闭不等于设备已经恢复。**

### 核心创新名称

**携证事件（Proof-Carrying Incident）**

每个 Incident 必须携带：

1. 数据来源与时间戳；
2. 诊断证据、缺失证据和冲突证据；
3. 资源约束下的候选方案；
4. 确定性策略检查与人工审批；
5. 执行记录；
6. 恢复验证结果；
7. Agent Trace 与可检测篡改的审计链。

### 北极星指标

**可验证事件闭环率 VICR**

```text
VICR =
具备最小证据集、审批记录、执行记录和恢复证明的已关闭事件数
÷
全部已关闭事件数
```

比赛阶段不虚构 VICR 数值；通过 Demo 样例和自动化测试验证计算条件。

## 3. 能力状态标注规则

所有对外材料统一使用三种状态：

- **已实现**：当前代码存在完整调用链，并有测试、构建或接口证据；
- **原型验证**：算法或服务已实现，但依赖模拟数据、降级逻辑，或尚未形成稳定前端入口；
- **计划接入**：只有接口、设计或路线图，不作为当前 Demo 成果宣称。

严禁把“原型验证”写成“已在真实风场生产部署”，严禁使用未验证的节省金额、准确率、告警压缩率或停机下降比例。

## 4. 初赛提交组合

建议提交以下组合：

1. 500 字以内作品简介；
2. 12 页方案 PDF；
3. 4 分钟 Demo 视频；
4. 可访问的代码仓库或只读压缩包；
5. README 中的“一键启动、示例账号、Demo 路径、数据与许可边界”；
6. 数据合规说明链接。

## 5. 提交前仍需用户确认的信息

以下内容无法从仓库可靠推断，制作最终封面和报名页前必须由参赛者确认：

- 最终参赛队名；
- 最多 3 名正式参赛成员及分工；
- 学校/单位标准名称；
- 仓库公开地址或材料下载地址；
- Demo 视频链接；
- 联系邮箱；
- 最终采用的开源许可证。

> 赛事手册规定团队人数不超过 3 人，而当前 README 列出了超过 3 名开发成员。最终提交不能直接照搬 README 的团队表。
