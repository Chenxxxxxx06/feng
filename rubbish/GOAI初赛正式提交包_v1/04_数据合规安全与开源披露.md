## 2. 数据对齐边界

公开 SCADA、振动和图像数据来自不同项目和不同设备，当前只用于：

- 方法演示；
- 工具调用；
- 数据质量与冲突处理；
- Demo 流程验证。

不得宣称这些数据来自同一台真实风机、同一时段或同一风场。跨数据集组合时必须标注 `method_demo_only_not_same_asset`。

## 3. 当前数据清单的待对齐项

当前 `local_dataset_inventory.json` 仍把部分数据标记为 `downloading` 或存在 importer gap，而仓库中已经出现部分提取文件。提交前应更新清单，使“本地状态、校验和、已导入样本数、许可状态”一致。

这不是数据清洗质量问题，而是**提交证据与当前磁盘状态不一致**的问题。

## 4. 模型与商业 API

| 模型/服务 | 用途 | 是否可替代 | 风险控制 |
|---|---|---|---|
| 通义千问 / DashScope | 意图理解、解释、知识提取 | 可替换为 OpenAI-compatible 或本地模型 | Key 不入库；调用写 Trace；失败时降级 |
| OpenAI-compatible | 可选模型后端 | 是 | 明确配置、费用和数据边界 |
| YOLOv8 / Ultralytics | 叶片缺陷检测 | 可替换为其他检测模型 | 输出保留模型版本、置信度、数据来源 |
| 规则与统计算法 | 约束、状态机、策略、恢复验证 | 核心安全依赖 | 确定性测试、版本记录 |

## 5. 工业安全边界

1. 系统定位为辅助分析和运维协同工具；
2. 不替代持证人员、场站制度和安全生产规程；
3. 比赛版本不直接控制真实风机；
4. LLM 输出不能直接改变设备或高风险业务状态；
5. 高风险动作必须经过 RBAC、前置条件、策略和人工审批；
6. 数据不足时输出 `insufficient_data`；
7. 所有模拟值、降级值和假设必须在 UI 与 API 中可见；
8. 未核验的法规条款只能作为内部检查规则，不能表述为法律结论。

## 6. 隐私与敏感信息

- 公开设备数据不包含个人身份信息；
- 演示账号不使用真实人员身份；
- 视频中遮挡账号密码、邮箱、API Key、Token 和本机敏感路径；
- 日志禁止记录明文密钥；
- 对外提交前扫描 `.env`、数据库、日志和截图；
- 如未来接入企业数据，应增加数据分级、最小权限、保留周期、审计和删除流程。

## 7. 可追溯与审计

- Evidence 记录来源、时间、置信度和关系；
- Agent Trace 记录步骤、输入输出摘要、耗时、错误和降级；
- SHA-256 链用于检测中间记录是否变化；
- Ed25519 根签名只有在配置 `AUDIT_SIGNING_KEY` 或 `AUDIT_SIGNING_KEY_PATH` 后才成立；
- 当前环境未配置审计签名密钥，因此材料不能宣称“当前签名验证已通过”；
- 审计链不是区块链，不宣称不可篡改，只宣称可检测篡改。

## 8. 开源披露

### 计划开放

- Incident / Evidence Contract 领域模型；
- 策略规则模板；
- Demo Playbook 与样例配置；
- OpenAPI 3.0 接口；
- Python SDK；
- 光伏、水泵、压缩机适配模板；
- 测试方法和部署说明。

### 当前阻塞

- 仓库根目录没有 `LICENSE`；
- README 写“仅供学习和研究”，初版 PPT 写“Apache 2.0”，两者冲突；
- 部分第三方数据为 CC BY-NC，不能把数据许可与代码许可混为一谈；
- 最终开源范围、许可证、模型权重和数据再分发边界尚未统一。

### 提交前动作

1. 选择并落地代码许可证；
2. 添加 `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`；
3. 分离“代码、模型、数据、文档”许可；
4. 对不能再分发的数据只提供官方下载脚本和校验和；
5. README 与 PPT 使用同一许可口径。
