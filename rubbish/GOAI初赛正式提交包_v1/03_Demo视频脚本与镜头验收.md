# 风调预顺 WindOps ProofLoop｜4 分钟 Demo 视频脚本

> Demo 唯一目标：证明一个 Incident 从异常到恢复验证的闭环。  
> 不要在 4 分钟内轮播所有页面。  
> 所有数字以录制当天真实响应为准，脚本中的示例值不得硬念。

## 0. 录制前提

1. 使用固定的 Demo 数据库副本，禁止直接使用日常开发库；
2. 一键启动后端和前端；
3. 默认账号仅用于本地 Demo，视频中遮挡密码；
4. 预先准备一个“齿轮箱振动异常”样例；
5. 审计签名若未配置，只讲“哈希链验证”，不讲“签名已验证”；
6. 录制前连续跑 3 次相同路径；
7. 所有失败分支必须是真实后端响应，不用前端动画伪造。

## 1. 时间轴与旁白

### 0:00–0:20｜一句话定义问题

**画面**

风场监控页快速切到 Incident 指挥中心。

**旁白**

“在风电运维中，发现异常并不等于完成运维。真正困难的是把分散证据变成可执行决策，并证明维修后设备确实恢复。风调预顺是一套面向风电运维的可验证闭环工业 Agent。”

**验收**

- 20 秒内说清用户、问题和产品类别；
- 不展示无关菜单。

---

### 0:20–0:45｜事件进入

**操作**

选择一个已准备的高风险 Incident，展示 Incident ID、风机、阶段和严重度。

**旁白**

“系统不把每条告警都当作独立任务，而是组织成一个 Incident。它将成为诊断、审批、执行、验证和审计的唯一主线。”

**验收**

- Incident ID 清晰可见；
- 不宣称固定“27 条压缩为 1 条”，除非本次接口真实返回该数字；
- 若告警压缩 UI 尚未完成，可在终端或 Swagger 展示真实响应。

---

### 0:45–1:25｜Agent 自主调查

**操作**

点击“自主调查”，展示调查步骤和 Trace。

**旁白**

“Agent 依次调用 SCADA、告警、振动、健康指数、RUL 和历史知识。每一步都有输入来源、结果摘要、耗时和状态；当模型或数据不可用时，系统降级到规则与统计流程，并明确标记降级。”

**验收**

- 调查结果不能点击后立即消失；
- 至少展示 5 个真实步骤；
- 展示 1 个 Trace ID 和多个 Span；
- 若某步为降级，主动解释，不隐藏。

---

### 1:25–1:55｜证据契约

**操作**

切换到“证据”，展示证据类型、来源、置信度、完整度和缺失项。

**旁白**

“普通 AI 只给一个答案；ProofLoop 先判断这个答案有没有资格进入下一步。证据契约会检查完整度、新鲜度和冲突。证据不足时只输出候选诊断，不允许把猜测写成确定事实。”

**验收**

- 完整度为接口真实值；
- 缺失证据可见；
- 至少一个证据节点能看到来源；
- 不口播固定 75%，除非本次响应正好为 75%。

---

### 1:55–2:35｜资源约束决策

**操作**

点击“决策分析”，展示四个方案、推荐项、不可行原因和数据质量警告。

**旁白**

“系统比较立即维修、降载运行、继续监测和先巡检四个方案。评分综合安全、经济、资源和恢复时间，并对硬约束先行判定。人员、备件或天气数据不足时，方案会显示不可行或数据质量警告，而不是假装资源已经准备好。”

**验收**

- 方案数量、名称以实际响应为准；
- 必须展示至少一个数据质量说明；
- 不把 `weather placeholder` 说成真实天气接入；
- 不把故障知识里的备件名称说成真实库存锁定。

---

### 2:35–3:05｜策略拦截

**操作**

从合法阶段发起“未验证直接关闭”，展示后端 403/409 响应或页面错误消息。

**旁白**

“现在尝试跳过验证直接关闭。服务器端策略网关拒绝请求。这个限制不在按钮上，即使直接调用 API 也无法绕过。大模型负责理解与解释，但没有直接改变高风险业务状态的权限。”

**验收**

- 后端响应必须为 403 或 409；
- 事件状态仍不是 resolved；
- 错误信息能被用户理解；
- 不只展示前端禁用按钮。

---

### 3:05–3:35｜恢复验证

**操作**

运行恢复验证，展示结果枚举、观察窗口、前后指标、剩余风险和证据哈希。

**旁白**

“维修后，系统比较振动、温度、功率、告警复发等指标，输出通过、有条件通过、失败或数据不足。只有满足策略条件，Incident 才允许关闭。数据不足也是一种结果，它阻止系统伪造确定性。”

**验收**

- 若结果为 `insufficient_data`，如实展示；
- 不为了视频强行改成 pass；
- 解释 observation window；
- 当前恢复证书未持久化时，不宣称可长期查询历史证书。

---

### 3:35–3:55｜审计与复盘

**操作**

打开审计页，展示 Entry 数、根哈希和链验证结果；再展示 Trace。

**旁白**

“每个 Agent Span 被组织成 SHA-256 哈希链，任何中间内容变化都可被检测。配置签名密钥后，根哈希还可用 Ed25519 签名。它不是区块链，而是面向工程审计的可检测篡改机制。”

**验收**

- 没配置签名密钥时不说“签名验证通过”；
- Entry 数以当前响应为准；
- 明确“可检测篡改”，不宣称“绝对不可篡改”。

---

### 3:55–4:00｜收束

**画面**

回到完整闭环图。

**旁白**

“风调预顺：预测只是开始，证明一次安全、有效、可追溯的恢复，才是闭环。”

## 2. 建议录制镜头

| 镜头 | 画面 | 必须出现的证据 |
|---|---|---|
| A | Incident 列表与详情 | Incident ID、阶段、严重度 |
| B | 自主调查 | 步骤状态、Trace ID、Span |
| C | 证据页 | 来源、置信度、缺失项 |
| D | 决策页 | 方案、不可行原因、质量警告 |
| E | 策略拒绝 | 403/409、状态未变化 |
| F | 恢复验证 | 枚举结果、指标、证据哈希 |
| G | 审计页 | Entry、根哈希、验证结果 |

## 3. 录制失败时的降级方案

- UI 某页不稳定：使用 Swagger 调真实 API，同时保留前后端日志；
- LLM 服务不可用：展示规则降级，并说明这是设计能力；
- 恢复数据不足：展示 `insufficient_data`，强调系统不会编造“已恢复”；
- 签名密钥未配置：展示哈希链，不展示签名通过；
- OPC 未接前端：不在主 Demo 中演示，把它放路线图。
