这些数据在 API 返回为空时作为兜底展示，但兜底值本身是写死的，无法反映真实情况。

### 2.1 DashboardPage.tsx — 关键部件温度兜底值

**位置**: `src/pages/Dashboard/DashboardPage.tsx:679-706`

## 六、功能空壳 / 未联通项 (🔴 高)

这些功能在 UI 上看起来可用，但实际数据链路是断的或依赖不可用后端。

### 6.1 AI 供应商模板依赖不可控外部 URL

**位置**: `src/pages/Settings/SettingsPage.tsx:147-155`

Ollama 本地模型的默认 URL `http://localhost:11434/v1` 硬编码。如果用户 Ollama 部署在其他端口，需要改代码。

---

### 6.2 天气数据依赖硬编码坐标

**位置**: `src/pages/Prediction/MaintenanceCalendar.tsx:92`

```tsx
api.get('/prediction/weather-windows', { params: { days: 60, lat: 37.3, lng: 107.6 } })
```

坐标 `(37.3, 107.6)` 写死，不随当前选中的风场而变化。且 60 天窗口固定。

---

### 6.3 个人设置 → 本地存储不一致

**位置**: `src/pages/Settings/SettingsPage.tsx:429-443`

```tsx
const savePersonalSettings = async () => {
  try {
    await api.put('/settings/preferences', payload);
    // ...
  } catch {
    // 服务器不可用时静默 fallback 到本地
    addLog('保存个人设置(本地)', `服务器不可用，已保存到本地`);
  }
};
```

**问题**: 当后端 `/settings/preferences` 不可用时，设置只存在 localStorage，刷新其他标签页或换浏览器后丢失。

---

### 6.4 创建工单表单 → 风机 ID 输入方式

**位置**: `src/pages/WorkOrder/WorkOrderPage.tsx:447-452`

创建工单时使用下拉选择风机 (基于 `/turbines/` 接口)。如果该接口返回空，用户无法创建工单。工单创建表单中 `assignee` 的责任人邮箱同步逻辑 (`form.assignee_email`) 依赖前端匹配，不经过后端校验。

---

### 6.5 聊天记录 → localStorage 持久化

**位置**: `src/services/copilotStore.ts:70-92`

AI 聊天记录使用 localStorage 持久化，存在以下问题：
- 不会同步到后端
- 清除浏览器数据则丢失
- 无法跨设备共享
